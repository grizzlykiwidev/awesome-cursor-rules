# Contributing

Thanks for helping! A good rule:

- Lives in `rules/<stack>/<name>.mdc` with `description`, `globs` and `alwaysApply` frontmatter.
- Is short (aim for under 40 lines) and specific: concrete do / don't items, ideally "old → new" tables.
- Targets current stable versions and says which version in the description.
- Has been used on a real project with at least one agent (Cursor, Claude Code, Codex...).

Add your rule to the table in `README.md` in the same PR. By contributing you agree your work is released under the MIT license.
